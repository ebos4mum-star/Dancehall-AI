# Native iOS flows that still need a real device

Nothing here has run on a device or simulator. Unit tests, the web export and mock-mode screenshots cover logic and layout only. Bundle identifier `com.dancehallfit.app`; a build needs an Apple Developer account and an EAS build (owner decisions, not started).

Run these with `EXPO_PUBLIC_AUTH_MODE=supabase` against the development project only, using a `development` or `preview` build, with paid AI, payments and HealthKit off.

## Device-only polish

- Haptics (`expo-haptics`) on Pulse celebrations and ticks; gentle and off modes respect the setting.
- Pulse celebrations: shown once across two devices (claim-before-display), never for weight or calories.
- Dark mode, Dynamic Type at the largest sizes, VoiceOver labels, safe-area and notch layouts on small and large iPhones, portrait lock.
- Guided workout player: background and foreground transitions (`AppState` listener in `src/player/usePlayer.ts`), screen lock, audio interruptions, video playback of licensed media.
- Splash screen, app icon, status bar, keyboard avoidance on forms.
- Deep link scheme `dancehallfit://` (declared; no flow depends on it yet).

## Not applicable yet (nothing to verify)

Coach and weekly review (server AI route not deployed, shows "not available"), photo analysis (simulated), purchases and entitlements (everyone is `free`), HealthKit (off), Sign in with Apple (not built; required only if another social sign-in is added), push notifications (none).
