## Live verification (2026-11-16): what was confirmed from the primary page and from the real service

Source: the Open Food Facts API introduction (`openfoodfacts.github.io/openfoodfacts-server/api/`), read on 2026-11-16. **Still not confirmed:** the separate "Terms and conditions of use and reuse" page and the ODbL wiki page (not read); the owner has not filled in the API usage form they ask for.

| Item           | Confirmed from the primary page                                                                                                                                                                                                                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identification | "always use a custom User-Agent ... in the form of AppName/Version (ContactEmail)". Reads need no authentication beyond it. The adapter now sends `DanceHallFit/0.0 (<public support address>)` when the owner has set `EXPO_PUBLIC_SUPPORT_EMAIL`; without one it sends the older form with no contact, which does not meet their request: **set a support address before enabling** |
| Rate limits    | **15 product reads a minute per IP address**, 10 searches a minute (we never search); they reserve the right to ban an address above it. The adapter had a 700 ms gap only (about 85 a minute), which was **too fast**; it now allows at most 12 real requests in any rolling minute and then answers "unavailable (rate limited)" without sending, with a plain message in the app   |
| Licence        | Database under ODbL; individual contents under the Database Contents License; product images CC BY-SA (the app uses no images). The in-app credit "Product data from Open Food Facts (open database, ODbL licence)" is shown with every OFF product                                                                                                                                   |
| Disclaimer     | The page states data is crowd-sourced and the user assumes the risk; the app already labels values as package data and approximate                                                                                                                                                                                                                                                    |

Real lookups (`DH_OFF_LIVE=1 pnpm --filter @dancehall/shared exec vitest run src/barcode-live.test.ts`, read-only, 3 requests): a common spread and a cola were found and mapped within physical limits (about 539 kcal per 100 g for the spread, plausible); an unlisted code returned "not found"; an invalid check digit made no request; a repeat was answered from memory; every request carried only `Accept` and `User-Agent` (no cookies, no personal data); the offline fallback served a remembered product and reported a never-seen one as unavailable. **7 of 7 PASS.** The feature remains OFF by default and in production; switching it on is still the owner's decision (privacy wording, support address, usage form, preview-first).

## Terms page and support address (2026-11-16)

- **Terms of use, contribution and re-use** (`world.openfoodfacts.org/terms-of-use`) was read. Confirmed: three licences (ODbL for the database, Database Contents License for contents, CC BY-SA for photos), commercial re-use allowed under attribution and share-alike conditions; contributors "agree to be credited by re-user by a link to the product"; no guarantee of accuracy; personal information they collect "will not be sold or transmitted to third parties"; data-rights contact `privacy@openfoodfacts.org`. The app now shows a link to the product page for every Open Food Facts product. Still not done by the owner: the API usage form the documentation asks for.
- **Support address:** **none is configured.** The repository contains no public support address (`docs/PRIVACY_SUPPORT_PUBLICATION.md` says so) and the EAS variables could not be read, so nothing was confirmed or invented. The only real address in the documents is the owner's personal account address used for administration, which is not a support mailbox and is **not** used. Until the owner sets `EXPO_PUBLIC_SUPPORT_EMAIL` to an address that receives mail, the User-Agent carries no contact (`DanceHallFit/0.0 (barcode lookup)`), which does not fully meet Open Food Facts' request.
- **Consent and wording:** the app asks before the first lookup and can be switched off in Privacy; draft policy wording is in `docs/OPEN_FOOD_FACTS_PRIVACY_DRAFT.md`.
